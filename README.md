# Telegram-бот-консультант на базе LLM

[English](README.en.md)

Отвечает клиентам на вопросы по вашему прайсу и FAQ — круглосуточно, своими словами, а не шаблонной кнопкой. База знаний — обычный markdown-файл: поменяли текст, отправили `/reload`, бот уже отвечает по-новому.

Работает на российских LLM — **GigaChat** (Сбер) или **YandexGPT**. Оплатить OpenAI или Anthropic напрямую из России нельзя, поэтому провайдеры отечественные; оба спрятаны за общим интерфейсом и переключаются одной переменной окружения.

## Что делает

1. Клиент задаёт вопрос в Telegram обычным текстом.
2. Бот выбирает из базы знаний разделы, относящиеся к вопросу, и собирает из них системный промпт.
3. Запрос уходит в LLM, ответ возвращается в чат. Пока идёт генерация — показывается индикатор «печатает».
4. Пара «вопрос — ответ» и расход токенов пишутся в PostgreSQL: видно, о чём спрашивают чаще всего и во что это обходится.

База знаний — `knowledge/faq.md`, читается при старте. Команда `/reload` перечитывает файл на лету, без перезапуска; доступна только администратору из `ADMIN_TG_ID`.

Поиск по базе — **RAG-lite, без векторов**: текст режется по заголовкам markdown, разделы отбираются по совпадению слов с лёгким стеммингом («оплаты» находит «оплата»). Для прайса и FAQ на несколько страниц этого достаточно, а векторная база и эмбеддинги — лишняя инфраструктура и лишние деньги.

## Запуск

Нужен Docker, токен бота от [@BotFather](https://t.me/BotFather) и ключ одного из LLM-провайдеров.

```bash
git clone https://github.com/matthewprokofiev/go-llm-consultant
cd go-llm-consultant
cp .env.example .env   # заполнить BOT_TOKEN и ключи провайдера
make cert              # скачать корневой сертификат Минцифры (нужен для GigaChat)
make up
```

Остановить: `make down`.

### Ключи провайдеров

**GigaChat** — [developers.sber.ru](https://developers.sber.ru/portal/products/gigachat-api). Нужен Authorization Key — это `base64(ClientID:ClientSecret)` из личного кабинета. Для физлица доступен фримиум: 1 000 000 токенов на 12 месяцев, scope `GIGACHAT_API_PERS`, платёжный профиль не требуется. Обязателен корневой сертификат Минцифры — его ставит `make cert`.

**YandexGPT** — [Yandex Cloud](https://yandex.cloud/ru/services/foundation-models). Нужны `folder_id`, сервисный аккаунт с ролью `ai.languageModels.user` и API-ключ. Переключение: `LLM_PROVIDER=yandexgpt`. Обратите внимание: бесплатный доступ без платёжного профиля отключён.

| Переменная | Обяз. | По умолчанию | Назначение |
| --- | --- | --- | --- |

## Технические решения

Полный журнал — в [docs/DECISIONS.md](docs/DECISIONS.md).

**Свой тонкий HTTP-клиент вместо SDK.** Каждому провайдеру нужно максимум два запроса: GigaChat — OAuth плюс chat, Yandex — один completion. Готовые Go-SDK для обоих сырые и мало поддерживаются, а зависимость пришлось бы тащить в прод. Интерфейс один:

```go
type LLMClient interface {
    Ask(ctx context.Context, systemPrompt, userMessage string) (Answer, error)
}
```

Провайдер выбирается одной строкой в фабрике `llm.New`. Добавить третьего — значит написать файл на ~150 строк, не трогая остальной код.

**Сертификат Минцифры.** Цепочка GigaChat подписана корневым сертификатом НУЦ Минцифры, которого нет в системном хранилище — без него клиент получает `x509: certificate signed by unknown authority`. Клиент читает PEM с диска и добавляет его в **копию** системного пула (`x509.SystemCertPool` + `AppendCertsFromPEM`), не подменяя его целиком, `MinVersion: TLS 1.2`. Сам сертификат в репозитории не лежит — его скачивает `make cert`.

**Кэш OAuth-токена.** Токен GigaChat живёт 30 минут. Клиент кэширует его на это время минус минута запаса и обновляет лениво под мьютексом. На `401` — один принудительный рефреш и одна повторная попытка, не бесконечный цикл.

**Лимит промпта.** Отобранные разделы упаковываются в порядке релевантности до `MaxPromptChars = 12000`. Без ограничения база знаний на несколько десятков страниц гарантированно даёт `400 Bad Request` — вместо этого лучше отдать модели самое релевантное.

**Таймауты.** У каждого запроса свой `context.WithTimeout` на 45 секунд, а `http.Client.Timeout` намеренно равен нулю: общий таймаут клиента обрубил бы долгую генерацию на середине, и пользователь получил бы обрыв вместо ответа.

## Разработка

```bash
make test   # тесты под -race
make lint   # golangci-lint зафиксированной версии
make cert   # корневой сертификат Минцифры в certs/
make run    # локальный запуск (переменные экспортировать в оболочке)
```

Тесты не ходят во внешние API: оба клиента проверяются через `httptest.Server`.

## Структура

```
cmd/bot/            точка входа, общий ctx и graceful shutdown
internal/config/    конфиг из ENV, валидация под конкретного провайдера, slog
internal/llm/       интерфейс LLMClient + gigachat.go + yandexgpt.go
internal/knowledge/ загрузка faq.md, нарезка по заголовкам, отбор разделов
internal/telegram/  Consultant (логика) + Bot (транспорт), /reload
internal/storage/   пул pgx, миграции goose, лог диалогов
knowledge/faq.md    пример базы знаний
certs/              корневой сертификат Минцифры (скачивается make cert)
docs/DECISIONS.md   журнал технических решений
```

Стек: Go 1.25, [go-telegram/bot](https://github.com/go-telegram/bot), собственный клиент на `net/http` + `crypto/tls` + `crypto/x509`, [pgx/v5](https://github.com/jackc/pgx), [goose](https://github.com/pressly/goose), `log/slog`, Docker Compose.

## Ограничения

- Форматы ответов обоих API проверялись на моках, не на боевых ключах: перед продом нужен прогон с реальными кредами.
- Бот отвечает по одному вопросу за раз — контекст диалога в промпт не передаётся, уточняющие вопросы вида «а сколько это стоит?» модель не свяжет с предыдущим.
- Отбор по ключевым словам проигрывает векторному поиску на больших и разнородных базах. Для прайса и FAQ этого хватает, для базы в сотни страниц — нет.
- Нет ограничения частоты запросов на пользователя: при публичном запуске токены выжигаются за день.
- Модель может ошибиться даже при точной базе знаний. Для чувствительных тем — цены, договорные условия — ответ должен вести к живому менеджеру, а не заменять его.
