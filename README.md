# Telegram-бот-консультант по базе знаний

[English](README.en.md)

Отвечает вашим клиентам в Telegram по прайсу, услугам и условиям — круглосуточно, своими словами.

- **Только по вашим материалам.** Цены называет точно как в прайсе, скидки не считает и ничего не выдумывает.
- **Честно говорит «не знаю».** Если ответа в материалах нет, бот так и говорит и предлагает передать вопрос администратору. На вопросы не по теме вежливо возвращает к делу.
- **Заявки и вопросы — вам в Telegram.** Имя, телефон и что интересует приходят владельцу в личку или в рабочую группу. Ответить клиенту можно прямо оттуда: reply на заявку — и бот перешлёт ответ.
- **Учится на ваших ответах.** Ответ на вопрос, которого не было в базе, можно одной кнопкой добавить в базу — только с вашего подтверждения.
- **Не хранит переписку.** Ни текстов, ни имён, ни телефонов — ни в базе, ни в файлах, ни в логах.
- **Российские нейросети.** GigaChat или YandexGPT; по желанию — любой сервис с API как у OpenAI.
- **Проверка до сдачи.** Экзамен на 20 вопросов с подвохами и понятный протокол для владельца.

## Как это работает

1. Клиент пишет вопрос обычным текстом. Внизу чата всегда есть кнопки «Оставить заявку» и «Контакты».
2. Бот выбирает из базы знаний разделы, относящиеся к вопросу (и к предыдущему — чтобы понять «а сколько это стоит?»), и собирает промпт с правилами: отвечать только по базе, цены дословно, инструкции из сообщения клиента не выполнять.
3. Модель отвечает и помечает ответ: по базе, частично, «в базе нет» или «не по теме». Метка вырезается, а бот решает, что предложить:
   - нет ответа или только часть — кнопка «Передать вопрос администратору»; отказ — бот даёт контакты бизнеса;
   - явное желание купить или записаться — ненавязчивое предложение оставить заявку, не чаще раза за разговор;
   - не по теме — просто текст, владельцу ничего не уходит.
4. Заявка собирает телефон (одной кнопкой «поделиться контактом» или вручную) и имя. Посреди заявки можно задать вопрос — бот ответит и вернётся к заявке. Согласие на обработку данных показывается, если владелец задал его в настройках.
5. Сообщение владельцу уходит с повторами до 5 минут: Telegram в России замедлен. Не получилось — клиент честно узнаёт об этом и получает контакты, чтобы позвонить.
6. Ответ владельца на вопрос без ответа бот предлагает добавить в базу знаний. Владелец видит, что именно запишется, и может заменить личный ответ общей формулировкой. После «Добавить в базу» бот сразу отвечает так всем, кто спросит похожее.

База знаний — обычный markdown-файл. Команда `/reload` перечитывает его без перезапуска. Для нового клиента есть утилита, которая собирает базу из его PDF, Word и таблиц, и экзамен — см. [инструкцию по настройке](docs/NEW_CLIENT.md).

## Запуск

Нужен Docker, токен бота от [@BotFather](https://t.me/BotFather) и ключ нейросети.

```bash
git clone https://github.com/matthewprokofiev/go-llm-consultant
cd go-llm-consultant
cp .env.example .env   # заполнить BOT_TOKEN, OWNER_CHAT_ID, BUSINESS_*, ключ нейросети
make cert              # корневой сертификат Минцифры (нужен для GigaChat)
make up                # бот без базы данных
```

Остановить: `make down`. Каждый бот — отдельный контейнер со своим `.env` и своей базой знаний, поэтому ботов разных клиентов можно держать на одном сервере:

```bash
ENV_FILE=clients/kadr/.env KNOWLEDGE_DIR=clients/kadr/knowledge docker compose -p kadr up -d --build
```

### Статистика (по желанию)

`make up-stats` поднимает рядом Postgres, и администратору становится доступна команда `/stats`: сколько вопросов за 7 и 30 дней, сколько без ответа и не по теме, сколько заявок доставлено и потеряно, сколько потрачено токенов. В базу пишутся только такие счётчики, время округлено до часа — ни текстов, ни имён, ни id пользователей там нет.

## Нейросети

**GigaChat** — [developers.sber.ru](https://developers.sber.ru/portal/products/gigachat-api). Нужен Authorization Key — `base64(ClientID:ClientSecret)` из личного кабинета. Персональный бесплатный пакет (scope `GIGACHAT_API_PERS`) годится для теста; для бота, который работает на бизнес, нейросеть подключается на аккаунт клиента (ИП или юрлицо, scope `GIGACHAT_API_B2B` или `GIGACHAT_API_CORP`), и клиент платит Сберу напрямую. Обязателен корневой сертификат Минцифры — его ставит `make cert`.

**YandexGPT** — [Yandex Cloud](https://yandex.cloud/ru/services/foundation-models). Нужны `folder_id`, сервисный аккаунт с ролью `ai.languageModels.user` и API-ключ. Бесплатный доступ без платёжного профиля отключён.

**Сервисы с API как у OpenAI** — ChatGPT, DeepSeek и другие. Подключаются только настройками: `LLM_PROVIDER=openai`, адрес, модель и ключ. ⚠️ С такими сервисами вопросы клиентов уходят на серверы за рубежом, а оплату сервиса клиент оформляет сам.

Все защиты работают одинаково для любого провайдера: правила честности в промпте, лимит размера промпта, таймаут 45 секунд, один повтор при сбое сети или сервера. Если нейросеть недоступна или ключ неверный, клиент получает «сейчас не могу ответить» и контакты бизнеса, а в логе остаётся техническая причина.

Всё задаётся в `.env`, код для нового клиента не меняется. Многострочный текст пишется одной строкой с `\n`.

| `BUSINESS_NAME` | да | — | Название бизнеса для клиентов |
| `BUSINESS_CONTACTS` | да | — | Телефон, адрес, часы работы: кнопка «Контакты» и запасной ответ |

| `LEAD_OFFER_ENABLED` | нет | `true` | Предлагать заявку, когда виден интерес купить или записаться |

## Технические решения

Полный журнал — в [docs/DECISIONS.md](docs/DECISIONS.md).

**Бот ничего не хранит.** Недавние сообщения (3 пары, 30 минут), шаг заявки и лимиты живут только в памяти и пропадают при перезапуске. На диск бот пишет только одно — ответы, которые владелец сам одобрил для базы знаний. В логах — только технические события: время ответа, токены, статус, доставлено ли сообщение владельцу. Ошибки Telegram очищаются перед логом: библиотека кладёт в них URL с токеном и тело ответа с сообщениями пользователей.

**Честность — в двух местах.** Промпт запрещает выдумывать и считать, а служебная метка статуса даёт боту решить, что делать дальше, без второго запроса к модели. Нет метки — ответ показывается как есть и ничего не предлагается.

**Свой тонкий HTTP-клиент вместо SDK.** GigaChat, как и сервисы с API OpenAI, говорит форматом `/chat/completions` — код запроса общий, у GigaChat сверху только OAuth и сертификат. YandexGPT — отдельный клиент. Интерфейс один:

```go
type LLMClient interface {
    Ask(ctx context.Context, messages []Message) (Answer, error)
}
```

**Сертификат Минцифры.** Цепочка GigaChat подписана корнем НУЦ Минцифры, которого нет в системном хранилище. Клиент добавляет его в **копию** системного пула, `MinVersion: TLS 1.2`. Сам сертификат в репозитории не лежит — его скачивает `make cert`.

**Кэш OAuth-токена.** Токен GigaChat кэшируется на срок жизни минус минута, переполучение схлопывается через `singleflight`. На `401` — один принудительный рефреш и одна повторная попытка.

**Лимит промпта и таймауты.** Разделы базы упаковываются по релевантности до 12 000 символов. У запроса свой `context.WithTimeout` на 45 секунд вместе с повтором, `http.Client.Timeout` намеренно равен нулю — иначе долгая генерация обрывалась бы на середине.

## Разработка

```bash
make test   # тесты под -race
make lint   # golangci-lint зафиксированной версии
make cert   # корневой сертификат Минцифры в certs/
go run ./cmd/kb -out draft.md файлы...                       # файлы клиента → черновик базы
go run ./cmd/exam -env .env -questions exam.csv -out exam    # экзамен
```

Тесты не ходят во внешние API: клиенты нейросетей проверяются через `httptest.Server`, Telegram-логика — на чистых функциях.

## Структура

```
cmd/bot/              бот: общий ctx и graceful shutdown
cmd/kb/               утилита «файлы клиента → база знаний»
cmd/exam/             экзамен: протокол для клиента и сводка расхода
internal/config/      настройки из ENV с умолчаниями и проверкой
internal/llm/         GigaChat, YandexGPT, OpenAI-совместимый API
internal/consultant/  ядро ответа: промпт, статусы, намерение, повтор
internal/knowledge/   база знаний: разделы по заголовкам и подбор
internal/telegram/    меню, заявки, передача вопросов, доставка владельцу
internal/storage/     Postgres для обезличенной статистики (по желанию)
internal/kbconv/      разбор PDF, DOCX, XLSX, CSV, TXT, MD
internal/exam/        вердикты, прогоны, HTML-протокол
knowledge/faq.md      демо-база фотостудии
examples/photostudio/ исходники демо в виде «файлов клиента» и вопросы экзамена
docs/                 журнал решений и инструкция по настройке клиента
```

Стек: Go 1.25, [go-telegram/bot](https://github.com/go-telegram/bot), свой клиент на `net/http` + `crypto/tls`, [go-pdfium](https://github.com/klippa-app/go-pdfium) (WebAssembly) в утилите базы, [pgx/v5](https://github.com/jackc/pgx) и [goose](https://github.com/pressly/goose) для статистики, `log/slog`, Docker Compose.

## Ограничения

- Нет поиска по смыслу: разделы подбираются по совпадению слов с лёгким стеммингом. Синонимы («суббота» и «выходные») модель свяжет, только если нужный раздел попал в подборку. Для прайса и FAQ на десятки страниц этого хватает, для базы в сотни страниц — нет.
- Из PDF берётся только текстовый слой: сканы и текст на картинках не распознаются, утилита помечает их в отчёте.
- Бот не хранит историю: у владельца нет статистики вопросов, кроме обезличенных счётчиков в режиме со статистикой. Память разговора — 3 последних обмена и 30 минут, до перезапуска.
- Заявка может потеряться при падении процесса: повторы доставки живут в памяти. При штатной остановке клиент получает честное сообщение и контакты.
- Ответ владельца пересылается клиенту, только если бот не перезапускался и прошло меньше 48 часов; пересылается только текст и только в одну сторону.
- Лимиты вопросов и заявок сбрасываются при перезапуске.
- База пополняется только ответами, которые владелец одобрил кнопкой; записи идут в конец файла в раздел «Ответы администратора» и не проверяются экзаменом, пока его не прогонят заново. Дубли вопросов не сливаются.
- YandexGPT и сервисы с API как у OpenAI проверены на заглушках; на живой модели проверен только GigaChat.
- Модель может ошибиться даже при точной базе. Поэтому перед сдачей — экзамен, а спорные вопросы бот передаёт человеку.
