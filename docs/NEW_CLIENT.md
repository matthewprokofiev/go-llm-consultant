# Настройка бота для нового клиента

Чеклист от «получил файлы» до «бот отвечает». Новый клиент — это папка с настройками и базой знаний, код не меняется. Всё клиентское держите в `clients/<имя>/`: папка исключена из git и из Docker-образа.

```
clients/kadr/
  files/           что прислал клиент
  knowledge/faq.md база знаний
  .env             настройки бота
  exam.csv         вопросы экзамена
  exam/            прогоны и протоколы
```

## 0. До заказа: прикинуть расход

- [ ] Спросить, сколько вопросов в месяц примерно приходит сейчас (в мессенджеры, звонками).
- [ ] Взять сводку последнего экзамена с похожей по объёму базой (или демо фотостудии): стоимость ответа × поток. Минимальный платёж провайдера — отдельной строкой: при малом потоке платить придётся его.
- [ ] Предупредить: нейросеть подключается на аккаунт клиента (ИП или юрлицо), клиент платит сервису напрямую. Бесплатный персональный пакет GigaChat — только для теста.

## 1. Материалы → база знаний

- [ ] Сложить файлы клиента в `clients/<имя>/files/`. Подходят PDF с текстом, Word (DOCX), таблицы (XLSX, CSV), TXT и markdown.
- [ ] Собрать черновик:
  ```bash
  go run ./cmd/kb -out clients/<имя>/knowledge/faq.md clients/<имя>/files/*
  ```
- [ ] Прочитать отчёт:
  - «не удалось» — сканы, картинки, вложенные объекты: текст с них перепечатать руками или попросить у клиента текстом;
  - объединённые ячейки и «ячеек больше, чем столбцов» — проверить, что позиции прайса не съехали;
  - предупреждения о секциях больше лимита и «вопрос тянет почти весь лимит» — разбить крупные секции.
- [ ] Вычитать черновик:
  - цены и условия ровно как у клиента — бот будет называть их дословно;
  - у каждой секции осмысленный заголовок со словами, которыми спрашивают клиенты: «Прайс: цены на съёмки, аренду залов…», а не «Лист1»;
  - убрать подписи вроде «Прайс-лист на 2026 год», пустые разделы и дубли;
  - адрес, часы работы и правила (бронь, отмена, оплата) — отдельными секциями.
- [ ] Проверить объём: перезапустить утилиту на готовом файле, в отчёте должно быть до 20 страниц (1 страница = 1 800 знаков). Больше — это опция «ещё 30 страниц».

## 2. Настройки

- [ ] Создать бота у [@BotFather](https://t.me/BotFather): имя, описание, аватар клиента.
- [ ] `cp .env.example clients/<имя>/.env` и заполнить:
  - `BOT_TOKEN` — токен нового бота;
  - `OWNER_CHAT_ID` — куда слать заявки. Личка владельца: владелец пишет [@userinfobot](https://t.me/userinfobot), тот показывает id. Рабочая группа: добавить бота в группу и узнать её id (начинается с `-100`), например временно добавив в группу бота вроде @RawDataBot;
  - `BUSINESS_NAME`, `BUSINESS_CONTACTS` — телефон, адрес, часы работы через `\n`;
  - ключ нейросети на аккаунте клиента; для сводки экзамена — `LLM_PRICE_*` и `LLM_MIN_MONTHLY` по текущим тарифам;
  - по желанию клиента: приветствие, тексты кнопок и подтверждений, `CONSENT_TEXT` и `PRIVACY_URL`, `LEAD_OFFER_ENABLED`;
  - `ADMIN_TG_ID` — свой id, чтобы делать `/reload` в течение гарантийных 7 дней.
- [ ] `KNOWLEDGE_PATH` не трогать: в Docker база монтируется в `knowledge/`.

## 3. Экзамен

- [ ] Заполнить `clients/<имя>/exam.csv` — 20 вопросов, из них 5 с подвохом. Образец — `examples/photostudio/exam.csv`. Столбцы: `вопрос;тип;ожидание`.
  - обычный: ключевые факты через `|`, можно основой слова — `3 500 ₽|1 час`, `обув|образ`;
  - подвох: `НЕ ЗНАЕТ` (скидки, несуществующие услуги), `НЕ ПО ТЕМЕ` (анекдот, спорт, стихи), запрещённый факт с `!` (попытка выманить или посчитать цену, сменить роль: `!100 ₽|3 500 ₽`).
- [ ] Прогнать:
  ```bash
  go run ./cmd/exam -env clients/<имя>/.env -questions clients/<имя>/exam.csv -out clients/<имя>/exam
  ```
  Другая модель для сравнения — переменной окружения поверх файла: `GIGACHAT_MODEL=GigaChat-2-Pro go run ./cmd/exam …`.
- [ ] Открыть `run-*.csv` в Excel, для строк «проверить вручную» вписать в колонку «итог»: `по базе`, `не знает`, `к делу` или `ошибка`. Пересобрать протокол:
  ```bash
  go run ./cmd/exam -env clients/<имя>/.env -report clients/<имя>/exam/run-….csv
  ```
- [ ] Ошибки лечить правкой базы (заголовки, формулировки), не промпта. После правки — прогнать заново: внизу сводки видно, что изменилось с прошлого прогона.

## 4. Запуск на сервере

- [ ] Один раз на сервере: `make cert` (сертификат Минцифры для GigaChat).
- [ ] Дать контейнеру право дописывать базу (ответы, одобренные владельцем): бот работает в контейнере под пользователем с uid 10001.
  ```bash
  sudo chown -R 10001 clients/<имя>/knowledge
  ```
- [ ] Запустить бота отдельным проектом:
  ```bash
  ENV_FILE=clients/<имя>/.env KNOWLEDGE_DIR=clients/<имя>/knowledge docker compose -p <имя> up -d --build
  ```
  Со статистикой для `/stats` — добавить `-f docker-compose.yml -f docker-compose.stats.yml`.
- [ ] `docker compose -p <имя> logs -f` — есть строка «бот запущен», нет ошибок конфигурации.
- [ ] Написать боту вопрос из базы, вопрос мимо базы и оставить тестовую заявку: она должна прийти владельцу, а reply на неё — вернуться в бот.

## 5. Сдача и 7 дней гарантии

- [ ] Отправить клиенту `protocol-*.html` — открывается в браузере и на телефоне.
- [ ] Показать владельцу: заявки приходят в личку или группу, ответить клиенту можно reply на заявку; ответ дойдёт, пока бот не перезапускался и прошло меньше 48 часов.
- [ ] Показать, как пополнять базу: после ответа на вопрос без ответа бот предлагает «Добавить в базу». Личный ответ («Анна, для вас…») не добавлять — ответить на предложение общей формулировкой.
- [ ] Через неделю-две заглянуть в раздел «Ответы администратора» в `faq.md`: перенести записи в подходящие секции, убрать дубли и прогнать экзамен.
- [ ] Неверный ответ в гарантийные 7 дней: поправить `clients/<имя>/knowledge/faq.md` на сервере → `/reload` от `ADMIN_TG_ID` → прогнать экзамен и убедиться, что ничего не сломалось.
